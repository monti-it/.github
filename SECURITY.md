# Security policy

This policy applies to every monti-it repository that doesn't publish its own
`SECURITY.md`.

## Reporting a vulnerability

Report vulnerabilities privately through GitHub:

1. Open the affected repository on GitHub.
2. Go to the **Security** tab.
3. Click **Report a vulnerability** and fill in the form.

Only the maintainers can see the report.

**Do not open a public issue, pull request or discussion for a vulnerability.**
A public report exposes users before a fix is available.

## What to include

- The affected repository
- The version, release or commit you tested against
- Steps to reproduce, with a proof of concept if you have one
- The impact: what an attacker can do, and under which conditions

## What to expect

monti-it is a small team, so everything below is best effort, not a
service-level commitment.

- We aim to acknowledge your report within 5 business days.
- We'll confirm whether we consider it a vulnerability and keep you updated on
  the fix in the report's thread.
- We coordinate the fix and its release before any public disclosure, and
  agree the disclosure timing with you. Please don't disclose the issue
  publicly until then.

## Supported versions

Only the latest version is supported: the default branch, and the latest
deployed version for applications. Fixes aren't backported to older releases
or branches.
